# 정식 나이스 개발 루프 (학교 PC용)

학교 PC에서 Claude Code와 정식 나이스를 같이 띄워 두고, 개발용 버튼이 목표까지 될 때까지
**실행 → 판정 → (실패 시) 진단 파일 확인 → 코드 수정 → 다시 실행**을 반복하는 도구입니다.

- `run.mjs`: 한 바퀴 실행. 확장 새로 불러오기 → 사이드패널 열기 → 개발용 버튼 클릭 → 판정 → 임시 문구 버리기.
  마지막 줄에 JSON 결과를 내고, 목표 달성이면 종료 코드 0, 아니면 1.
- `cdp.mjs`: Chrome 디버깅 포트 연결 도구.

## 목표 (이 조건을 모두 만족하면 끝)

1. 개발용 버튼 상태줄이 `완료:`로 끝남
2. 입력 가능한 학생 행 수 = 이름이 맞게 들어간 행 수 (한 칸도 밀리지 않음)
3. 입력 가능한 학생 행 수 = 글자수(바이트) 칸이 바뀐 행 수 (나이스 내부까지 반영됨)
4. 버튼이 입력 부족으로 진단 파일을 저장하지 않음
5. 끝난 뒤 임시 문구를 저장 없이 버림

`run.mjs` 결과의 `"목표달성": true`가 이 조건을 모두 만족했다는 뜻입니다.

## 개인정보 규칙 (반드시 지킬 것)

정식 나이스 화면에는 학생 이름과 학생부 문구가 있습니다. 화면 내용이 AI(Claude)로 전송되지 않도록 다음을 지킵니다.

- 화면 정보는 **`run.mjs` 출력과 진단 파일(`neis-진단-*.json`)로만** 봅니다. 둘 다 학생 이름·문구가 없거나 ▒▒▒로 가려져 있습니다.
- 나이스 탭의 DOM 원문, 텍스트, 스크린샷을 직접 읽지 않습니다 (Playwright/Chrome 도구의 snapshot·screenshot·get_page_text 금지).
- 진단 파일을 고칠 때 학생 이름이 보이면 작업을 멈추고 사람에게 알립니다 (가리기 규칙을 먼저 고침).
- 진단 파일과 결과를 커밋하거나 외부에 올리지 않습니다.

## 안전 규칙

- 나이스의 **저장·삭제·일괄적용 버튼은 절대 누르지 않습니다.** 스크립트도 누르지 않습니다.
- 나이스 페이지를 새로고침하지 않습니다 (열린 화면과 세션이 사라짐).
- 저장 여부를 묻는 창에는 `아니오`만 누릅니다. 처리 방법을 모르는 창이 뜨면 멈추고 사람을 부릅니다.
- 2차인증은 사람이 직접 합니다. 스크립트는 기다리기만 합니다 (최대 3분).

## VPN 때문에 Claude Code 와 나이스를 같이 못 쓸 때: 단계별 화면 수집 (Windows)

VPN 을 켜면 인터넷이 끊겨 Claude Code 를 쓸 수 없는 경우, 아래처럼 **VPN 을 켠 채 버튼을 한 번 누르고, VPN 을 끈 뒤 파일 하나만 전달**합니다.
Node.js·디버깅 Chrome 은 필요 없습니다. 평소 쓰는 Chrome 에서 하면 됩니다.

1. 받은 압축 파일을 `C:\neisshot` 같은 곳에 풉니다 (`manifest.json` 이 보이는 폴더).
2. Chrome 주소창에 `chrome://extensions` → 오른쪽 위 **개발자 모드** 켜기 → **압축해제된 확장 프로그램을 로드합니다** → 1번 폴더 선택.
   웹스토어판 나이스입력도우미가 있으면 잠시 꺼 둡니다 (둘 다 켜져 있으면 어느 쪽 사이드패널인지 헷갈림).
3. VPN 을 연결하고 같은 Chrome 에서 나이스에 로그인합니다.
4. 나이스 탭에서 확장 아이콘을 눌러 사이드패널을 열고, 맨 아래 **개발용** 칸의 **"위 동작 + 단계별 화면 구조 수집 (파일 1개 저장)"** 을 누릅니다.
   어느 메뉴를 보고 있든 상관없습니다 (새로고침하지 않고 메뉴를 처음부터 눌러 들어감).
5. 2차인증 창이 뜨면 번호를 넣습니다. 늦게 넣어도 3분까지는 기다립니다.
6. 사이드패널 상태줄에 **"단계별 수집 파일 저장 (다운로드 폴더): neis-단계수집-날짜-시각.json"** 이 나오면 끝입니다.
   - 도중에 멈춰도 멈춘 곳까지 저장됩니다. 상태줄의 "실패 (…)" 문구도 같이 알려 주세요.
   - 화면에 `[임시 1] …` 문구가 들어가 있습니다. **저장 버튼은 누르지 말고** [조회]를 다시 눌러 버립니다 (저장 여부를 묻는 창이 뜨면 **아니오**).
   - Chrome 설정의 "다운로드 전에 각 파일의 저장 위치 확인"이 켜져 있으면 저장 창이 뜹니다. 다운로드 폴더에 저장하면 됩니다.
7. VPN 을 끊고 `C:\Users\(사용자)\Downloads\neis-단계수집-….json` 을 메모장으로 엽니다.
   `Ctrl+F` 로 반 학생 이름 몇 개를 찾아 **안 나오는지** 확인한 뒤 전달합니다.
   (학생 이름·문구·상단 사용자 정보·알림 내용은 ▒▒▒ 로 가려지고, 명단과 한 번 더 대조해 남은 이름도 가립니다.
   파일 안 `가리기점검.추가로가린곳` 이 0 이 아니면 그것도 알려 주세요.)

파일에 담기는 것: 단계마다(시작 → 메가메뉴 → 왼쪽 메뉴 → 2차인증 창 → 화면 열림 → 학년·반 목록(비어 있어 고를 때만) → 조회 결과 → 입력 후/멈춘 곳)
가린 화면 구조와 요약, 단계별 걸린 시간, 입력 결과, Chrome·Windows 버전. 크기는 보통 수백 KB~수 MB 입니다.
받은 쪽에서는 이 파일로 모의 나이스를 실제 화면에 맞게 고치고, 스크립트를 고친 뒤 다시 압축해 보냅니다.

## 준비 (한 번만)

1. **Node.js 22 이상**: `node -v`로 확인합니다.
2. **디버깅 포트를 연 Chrome을 따로 띄웁니다.** 평소 쓰는 Chrome 프로필로는 디버깅 포트가 열리지 않으므로, 별도 프로필 폴더를 씁니다.
   - Windows (PowerShell):
     ```powershell
     & "C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222 --user-data-dir="$env:USERPROFILE\neis-dev-chrome"
     ```
   - macOS:
     ```bash
     "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --remote-debugging-port=9222 --user-data-dir="$HOME/neis-dev-chrome"
     ```
3. 그 Chrome 창에서 `chrome://extensions` → 개발자 모드 켜기 → **압축해제된 확장 프로그램을 로드합니다** → 이 저장소 폴더(`manifest.json`이 있는 폴더)를 고릅니다.
   웹스토어판 나이스입력도우미가 설치돼 있으면 이 창에서는 꺼 둡니다.
4. 같은 창에서 **나이스에 로그인**합니다. 인증서 로그인도 이 창에서 하면 됩니다.
5. 연결 확인: `node tools/neis-dev-loop/run.mjs --discard` → `"목표달성": true`(임시 문구 없음)가 나오면 준비 완료입니다.

포트를 9222가 아닌 다른 번호로 띄웠다면 `CDP_PORT=번호`를 붙입니다. 다운로드 폴더가 기본(`~/Downloads`)이 아니면 `NEIS_DIAG_DIR=경로`를 붙입니다.

## 한 바퀴 실행

```bash
node tools/neis-dev-loop/run.mjs
```

- 진행 상황은 표준 오류로, 최종 결과(JSON)는 표준 출력으로 나옵니다.
- `👤 2차인증 창이 떴습니다` 가 나오면 사람이 인증합니다. 인증하면 이어서 진행됩니다.
- 옵션: `--no-reload`(코드 안 바꿨을 때), `--keep`(임시 문구를 사람이 눈으로 보도록 남김, 확인 후 `--discard`), `--discard`(버리기만).

결과 예:

```json
{
  "목표달성": false,
  "사유": ["글자수 칸이 안 바뀐 행 1개 (나이스 내부 미반영 의심, 행 번호 28)"],
  "검증": { "입력가능행": 28, "이름일치": 28, "글자수바뀜": 27, "글자수안바뀐행": [28], ... },
  "진단파일": ["C:\\Users\\...\\Downloads\\neis-진단-20261016-101500.json"]
}
```

## 예상 못한 실패도 처리되는 방식

| 상황 | run.mjs 동작 |
|---|---|
| 코드 수정 중 문법 오류 | 나이스에 손대기 전에 `node --check`·manifest 점검 → "코드 문법 오류 → 파일:줄" |
| 버튼을 눌러도 반응 없음 (스크립트 실행 오류) | 15초 뒤 "버튼을 눌러도 반응이 없음"으로 끝냄 (6분 기다리지 않음) |
| 버튼이 멈춰 끝나지 않음 | 6분 뒤 끝내고 지금 화면 진단 파일 저장 |
| 버튼은 완료인데 검증 실패 | 지금 화면 진단 파일 저장 |
| 처음 보는 단계·화면 구조 | 단계별 시간 제한 → "실패 (단계): …" + 진단 파일 |
| 처음 보는 알림창 | 멈추고 진단 파일 (창 이름만, 내용은 가림) |
| 진단 파일에 학생 이름이 남음 (가리기 실패) | 화면의 학생 명단과 대조해 발견하면 파일 이름을 `…가리기실패-사람확인`으로 바꿔 격리, Claude 에게 넘기지 않고 "사람 확인 필요" |
| 임시 문구를 못 버림 | "사람 확인 필요" → 사람이 저장하지 말고 다시 조회 |
| Chrome 종료·세션 끊김·확장 불러오기 실패 | "스크립트 오류: …" 로 끝남 (사람이 Chrome·로그인 상태 확인) |

어떤 경우든 같은 사유가 2번 연속 고쳐지지 않거나 8바퀴를 넘기면 Claude Code 가 멈추고 보고합니다.

## 수정할 곳 안내 (Claude Code 참고)

| 사유에 나오는 단계 | 볼 곳 |
|---|---|
| 상단 역할 메뉴, 메가메뉴 폴더, 왼쪽 화면 메뉴 | `dev-tools.js` `runNeisQuery` 1~3단계 선택자 (`li.cl-navigationbar-item`, `.cl-navigationbar-menu a[role=link]`, `.rolemenu a.cl-leaf`) |
| 화면 열기 / 2차인증 | 4단계: 탭 이름 `선택됨, 행동특성및종합의견`, 인증 창 판별(`aria-label`에 '인증') |
| 조회조건 | 5단계: 콤보 `aria-label="학년, 3"` 형식, 펼친 목록 `[role=listbox] [role=option]` |
| 조회 결과 | 6단계: 학생 행 `[role=row][aria-rowindex]`, 가림막 `.cl-loadmask` |
| 이름 불일치 | 7단계 명단(칸 이름 `N행 성명 이름`)과 `sidepanel.js` `findGridContext`의 행 순서 |
| 글자수 칸 안 바뀜 | `sidepanel.js` `fillInput` (값 확정 이벤트: input/change/blur, 마지막 행 확정) |
| 진단 파일 가리기 | `dev-tools.js` `collectNeisDiag` 의 `SAFE` 목록과 `maskLabel` |

## 참고

- 이 폴더(`tools/`)는 확장 프로그램 폴더 안에 있어서, 웹스토어용으로 압축할 때는 빼고 압축해야 합니다.
- `manifest.json`의 `http://127.0.0.1/*` 권한은 모의 나이스용이므로 출시 전에 뺍니다.
