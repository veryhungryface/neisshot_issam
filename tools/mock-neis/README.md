# 브라우저 자동화 연습장 — 모의 나이스 · 모의 K-에듀파인

> **나이스입력도우미 저장소의 복사본** (`tools/mock-neis/`, 2026-11-24 복사).
> 원본은 kev-ultrafast 의 `automation-sandbox` 입니다. 이 저장소에서는 확장 프로그램 시험에 맞게 이 복사본을 고쳐 쓰고, 고친 내용도 여기서 커밋합니다.
> 정식 나이스 로그에 맞춰 바꾼 것 (과세특 학생부 표):
> - 칸은 누르기(mousedown)로만 입력칸이 열리고, 열 때 칸을 새로 그린다 (`neis/cl.js`)
> - 보이는 행 아래 가려진 행을 더 그리고, 스크롤 막대는 행 단위로만 멈춘다. 가려진 칸을 누르면 안 열린다
> - 행 상자는 `scrollIntoView` 로 움직이지 않는다 (`neis/neis.css` 의 `overflow: clip`)
> - 이미 열린 화면을 메뉴로 다시 열면 0.7초 뒤 화면을 초기화한다 (`neis/app.js` `openScreen`)


실제 나이스·에듀파인에 손대지 않고 브라우저 자동화(kev-ultrafast, Playwright 스크립트 등)를 연습하고 채점하는 로컬 사이트입니다.
**모든 이름·문서·숫자는 가짜**입니다. 화면 구조는 2026-10-11에 수집한 실제 화면의 DOM 규칙을 따릅니다. 실명이나 문서 제목은 들어 있지 않습니다.

## 실행

- 맥: `연습장_실행.command` 더블클릭 → 브라우저에 시작 페이지가 열립니다.
- 윈도우: `연습장_실행.bat` 더블클릭 (Python 3 필요)
- 직접: `python3 server.py --port 8770` → <http://127.0.0.1:8770/>

외부 인터넷이 필요 없습니다. 파이썬 표준 라이브러리만 씁니다.

| 주소 | 내용 |
|---|---|
| `/` | 시작 페이지: 시나리오 목록, 채점, 상태 초기화 |
| `/neis/` | 모의 나이스 |
| `/edufine/` | 모의 K-에듀파인 |
| `/__sandbox/check?id=N1` (`id=all`) | 시나리오 채점 결과(JSON) |
| `/__sandbox/log` · `/__sandbox/state` | 동작 기록 · 현재 데이터 |
| `POST /__sandbox/reset` | 처음 상태로 되돌리기 |
| `/__sandbox/log?since=N` | N번째 이후 동작 기록 |
| `/__agent/*` | 화면 패널 → kev-ultrafast 연습 브리지(127.0.0.1:8767) 중계 |

**연습용 고정값**: 나이스 2차인증 번호 `000000`, 에듀파인 전자서명 비밀번호 `0000`. 실제 비밀번호는 넣지 마세요.

## kev-ultrafast로 연습하기

1. 연습장을 켜 둡니다.
2. kev-ultrafast 데모의 "직접 입력 URL"에 `http://127.0.0.1:8770/neis/`(또는 `/edufine/`)를 넣습니다.
3. 시작 페이지의 시나리오 목표 문장을 그대로 과제로 줍니다.
4. 끝나면 시작 페이지에서 **채점**을 누릅니다. 다음 시나리오 전에는 **상태 초기화**를 누릅니다.

## 화면 안에서 에이전트에게 요청하기

모의 나이스·에듀파인 오른쪽에 **AI 에이전트에게 요청** 패널이 있습니다. kev-ultrafast의 `./scripts/start.sh`가 켜져 있어야 동작합니다 (꺼져 있으면 패널에 "에이전트 꺼짐"이 보입니다).

1. 시나리오를 고르거나 요청을 직접 적습니다.
2. **실행**(자동) 또는 **한 단계씩 실행**. 기본으로 실행 전에 연습 데이터와 화면을 처음 상태로 되돌립니다.
3. 상신·결재·삭제·회수 같은 버튼 앞에서는 패널이 **누르게 할지** 묻고, 2차인증·전자서명은 **사람 차례**로 넘깁니다.
4. 끝나면 채점 결과(시나리오일 때)와 이번 실행 동안 서버에 남은 기록이 나옵니다. 굵은 줄이 데이터를 바꾸거나 바꾸려 한 동작입니다.

패널 요청은 이 서버의 `/__agent/*`를 거쳐 `127.0.0.1:8767`(kev-ultrafast 연습 브리지)로 갑니다. 같은 주소의 페이지만 보낼 수 있고, 브리지는 이 연습장 탭에만 붙습니다.

## 실제와 같게 만든 것

**모의 나이스 (eXbuilder6 규칙, 2026-10-12 학교 PC 수집으로 모양까지 맞춤)**
- 배치와 색: 로고 · 파란 상단 바(학교, 사용자, 세션 시간, 로그아웃/튜토리얼/사용자지원) · 역할 메뉴 줄, 왼쪽 아이콘 줄 + 패널
  (기본메뉴 및 승인사항 / 화면 메뉴 / 나의 할일 / 메뉴 검색 / 즐겨찾기 / 개인설정), 메뉴 접기 손잡이, **아래쪽 MDI 탭 줄**(초기화면, 목록보기, 전체화면)
- 초기화면: 월간일정 달력, 학교일지/전달사항, 업무요청내역
- 화면 틀: 제목(h1) + 위치 버튼(⌂ …화면명) + [A A] + 아이콘 버튼(도움말·질의응답·FAQ·연락처·온라인컨텐츠·즐겨찾기) + 축소 + [조회숨김], 회색 조회조건 상자, 목록 제목 + Total + 필터(톱니)
- 역할 메뉴: 역할을 누르면 메가메뉴(1·2단계)가 열리고, 2단계 폴더를 누르면 메가메뉴가 닫히며 **왼쪽 '화면 메뉴'에 그 갈래가 펼쳐짐** → 화면은 왼쪽에서 고름 (실제와 같음)
- `cl-*` 클래스, 접속할 때마다 바뀌는 `uuid-*` id, 역할 메뉴(메가메뉴, 늦게 그려짐), 기본 메뉴는 list/listitem 구조(폴더만 `role=menuitem`, 하위 목록은 숨긴 채 DOM에 있음)
- 글자 버튼은 aria-label 없이 글자로 이름이 붙고(회수, 확인, 승인요청), 아이콘 버튼만 aria-label이 있음 — 실제와 같음
- 표: 두 줄 머리글(초과근무 신청시간 › 시작/종료/시간합), 칸 이름 "N행 열 값", 마지막 행 "N행 마지막 행 …", 행 체크박스 "N행 선택 행선택 체크박스", 넓으면 가로 스크롤
- 날짜 칸은 **실제 키 입력만 받는 마스크 입력**: 자동화가 글자를 밀어 넣으면(insertText) 값이 안 바뀌고, 달력에서 고르면 바뀜 (학교 PC 시험에서 본 그대로)
- 달력 팝업 날짜 버튼 이름 "2026년 10월 12일 월요일", 알림 `modal-msg`, 에러 `modal-msg-danger`, 2차인증

**학생부 문구 입력 화면 (세특·독서·행특·창체·진로희망)**
- 과목별세부능력및특기사항, 과목별독서활동, 행동특성및종합의견, 독서활동상황기록, 진로희망사항기록, 자율활동관리, 진로활동관리, 동아리활동관리(담임용)
- 처음 열 때 2차인증(연습 번호 000000) → 필수 조회조건(*학년도/*학기/*학년/*과목/*강의실 또는 *학년도/*학년/*반, 기본값 "-없음-")을 고르고 [조회]
- 조회 전에는 표에 "데이터를 조회해 주십시오."와 회색 버튼, 조회하면 가짜 학생 28명
- 문구 칸은 표 안의 글상자(이름 "N행 세부능력및특기사항" 처럼 띄어쓰기 없는 열 이름), 옆 칸에 바이트/글자수가 바로 바뀜
  (나이스 규칙: 한글 3바이트, 영문·숫자·공백 1바이트, 줄바꿈 2바이트. 넘으면 빨간색, 저장 시 에러)
- [저장] → "저장하시겠습니까?" 확인 → "저장되었습니다." / [삭제]는 체크한 학생 / [일괄입력]·[일괄적용]은 체크한 학생에게 같은 문구 / [+]·[−]는 입력창 높이
- 학생부자료기록·누가기록 탭, 누가기록 작성 ON/OFF (누가기록 탭은 안내만)

**개인초과근무관리 (실제 흐름 재현)**
- 화면: 년월 조회, 인적사항 표, 총 초과근무확인/인정시간, 초과근무목록(7건, 가짜), 신청(새 창 열기)·회수·기결취소·삭제
- 신청 창: 지시문 4줄, **초과근무신청목록**(오늘 2026-10-11 행 하나가 기본으로 들어 있음), 기간 + [추가] + 휴일제외, 행추가/행삭제,
  아래 상세(초과근무일자·종별·휴일·시:분~시:분·시간합·방과후차감·하여야 할 일·대체휴무)는 **선택한 행에 묶여 있음**, [승인요청]
- 승인요청: 이미 신청한 날짜가 있으면 "…이미 신청하였거나, 진행중입니다" 알림 후 그 행이 목록에서 빠짐.
  목록이 0건이면 기안문서상신 창이 열리며 "…poParams.dataset.getRowCount()는 0건" 에러, 상신 비활성 — 학교 PC에서 에이전트가 겪은 그대로
- 기안문서상신 창: 결재문서명, 결재자 + 개인결재선/결재자지정, 내용, 결재구분(결재/검토/협조/공람), 결재선 표와 순서 버튼, 기안내용, [상신]/[취소]
- 회수는 결재 완료 건이면 거절, 삭제는 결재 중/완료 건이면 거절, 기결취소는 요청으로 기록
- 승인사항 > 상신함에서 상신한 문서를 볼 수 있음

**모의 K-에듀파인 (넥사크로 + JSP 규칙)**
- 점이 든 계층 id(`…WorkFrame.winId_<메뉴코드>_<n>.form.divWork.form.edtCnsulSj`)
- 컴포넌트 루트 클래스(Button/Edit/Combo/Calendar/Grid…), 이름 끝 공백
- 왼쪽 메뉴 트리: 보이는 줄만 존재하고, 본문 전체가 `role="gridcell"`
- 버튼 권한 접두어 `btnAuthS/P/D/R/C`, MDI 창과 아래쪽 탭, 10개 제한 알림
- 문서관리 화면은 iframe 안의 JSP 페이지(`#LblockWrapper`, `form[name=aform]`, `.LblockButton/.LblockSearch/.LblockListTable`)
- 새 창 팝업(문서보기·기안작성·결재요청), 전자서명 비밀번호 단계

**화면 수**: 나이스 163개, 에듀파인 53개는 수집 구조로 자동 생성됩니다(조회하면 가짜 행이 나옴). 아래 흐름은 실제로 데이터가 바뀝니다.
- 나이스: 개인초과근무관리(신청·저장·상신·회수·삭제), 개인근무상황관리(신청·상신), 과목별출결관리(조회·표 편집·저장)

## 한계

- 콤보박스 목록(listbox)과 달력 팝업은 수집 자료에 없어 일반적인 형태로 만들었습니다.
- 넥사크로 내부 동작(데이터셋, 이벤트 순서)은 흉내 내지 않습니다. DOM 겉모습과 접근성 속성만 맞췄습니다.
- 자동 생성 화면의 버튼은 동작 기록만 남기고 데이터는 바꾸지 않습니다.
